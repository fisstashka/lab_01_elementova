## Метод

Корпус (books.toscrape.com + синтетический корпус) приводится к нижнему регистру и токенизируется регулярным
выражением по латинским словам; токены короче 3 символов отбрасываются. Индексируется
объединённый текст `title + description + genre`. Инвертированный индекс — словарь
`термин -> множество doc_id`; документ входит в posting list термина ровно один раз.
Булев поиск: AND — пересечение posting lists, OR — объединение.

## Вывод

В лабораторной работе выполнено индексирование текстового
корпуса для варианта 14. Использована выборка из
1250 документов с random_state = 114.
Минимальная длина токена составила 3 символа, а основной
оператор поиска — AND.

Размер построенного словаря составил 21169 уникальных
терминов. Время построения индекса — 0.199776 секунды.
При увеличении минимальной длины токена с 1 до 5 размер словаря
изменился с 21445 до 18263 терминов.
Это объясняется исключением коротких токенов.

При изменении размера выборки от 100 до 1250 документов размер
словаря изменился с 4729 до 21169 терминов.
Время построения индекса зависит от объёма обрабатываемого текста.

Запрос AND вернул 52 документов, а запрос OR —
505 документов. AND выбирает документы, содержащие все
термины запроса, тогда как OR допускает наличие хотя бы одного.
Поэтому выдача AND является подмножеством выдачи OR.

Медианное время поиска по индексу составило
10.6 мкс, а полного перебора —
146494.5 мкс. Измеренное ускорение составило
13783.83 раза. Индекс позволяет быстрее выполнять
повторные запросы, поскольку списки документов уже подготовлены.
Цена ускорения — дополнительная память и время на построение
индекса. Таким образом, цель лабораторной работы достигнута.
